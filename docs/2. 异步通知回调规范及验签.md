# 通知协议定义及说明


|           |                                                                                                                |
| --------- | -------------------------------------------------------------------------------------------------------------- |
| **交互方式：** | 由皓臻支付服务器以 **HTTP** 请求的方式通知到商户的应用服务器                                                                            |
| **请求格式：** | http post方式，以 **json body** 形式提交参数                                                                             |
| **编码格式：** | 请求参数：Content-Type = application/json同步回调：Content-Type = application/json异步回调：Content-Type = application/json |
| **字符格式**： | UTF-8                                                                                                          |


# 响应回复约定

当皓臻支付开放平台回调到您的业务应用接口时，当您处理成功回调的业务逻辑时请确保业务回调接口响应体成功返回 **“success”** 内容，并且HTTP状态码返回**200**。如果返回其他内容或状态码，系统将认为通知失败并重试。


| 处理状态 | HTTP状态码 | 响应体内容      |
| ---- | ------- | ---------- |
| 成功   | 200     | success    |
| 失败   | 非200    | 非“success” |


# 通用回调参数


|            |        |        |               |
| ---------- | ------ | ------ | ------------- |
| **参数名**    | **类型** | **必须** | **描述**        |
| merchantNo | String | 是      | 平台分配的商户唯一标识   |
| timestamp  | Long   | 是      | 请求发送时的毫秒级时间戳  |
| sign       | String | 是      | 签名值，用于验证请求合法性 |


# 业务回调参数

业务回调参数会平铺到回调接口的请求Body体中，需要注意的是，在您进行签名校验的时候请务必剔除掉 sign字段，再进行签名的计算，最后进行检验签名是否匹配。

# 签名机制

## （一）签名生成（平台侧）

1. 收集所有非空参数（含公共参数和业务参数，排除sign字段）
2. 按参数名字典序升序排序
3. 按“参数名=参数值”格式用&拼接成字符串（例：merchantNo=M123&orderNo=O456）
4. 用SHA256算法对字符串生成摘要
5. 用平台私钥对摘要进行RSA算法加密，得到sign值

## （二）签名验证（商户侧）

1. 接收请求参数，剔除sign字段
2. 按与平台相同规则排序并拼接字符串
3. 用SHA256算法生成摘要
4. 用平台提供的公钥对请求中的sign值进行RSA解密，得到平台摘要
5. 对比本地生成的摘要与解密后的平台摘要，一致则验签通过

# 回调规范

在处理皓臻开放平台的任何回调前，**请您务必先进行签名校验**，防止恶意用户进行伪造，造成不必要的资金损失。
