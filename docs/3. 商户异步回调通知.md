# 一、接口说明

### 1.1 功能描述

皓臻支付系统会在支付、退款等业务完成后，通过 HTTP POST 方式异步通知商户系统处理结果。

### 1.2 通知场景

- 支付回调通知：订单支付成功/失败后通知
- 退款回调通知：订单退款成功/失败后通知

### 1.3 重试机制

如果商户系统未正确响应（HTTP 状态码非 200 或响应内容不是 "success"），系统将按以下策略自动重试：


|      |      |
| ---- | ---- |
| 重试次数 | 重试间隔 |
| 1    | 10秒  |
| 2    | 30秒  |
| 3    | 60秒  |
| 4    | 2分钟  |
| 5    | 5分钟  |
| 6    | 10分钟 |
| 7    | 30分钟 |
| 8    | 60分钟 |
| 9    | 2小时  |
| 10   | 4小时  |


**说明**：

- 最大重试次数为 10 次
- HTTP 请求超时时间为 5000ms（5秒）
- 超过最大重试次数后将停止通知并发送告警

## 二、支付回调通知

### 2.1 接口要求

- 请求方式: POST
- Content-Type: application/json
- 通知地址: 商户在创建订单时提供的 notifyUrl

### 2.2 请求参数

请求体（JSON格式）：

```JSON
{
  "orderNo": "20231128123456789",
  "merchantNo": "M123456",
  "orderAmount": 100.00,
  "payAmount": 100.00,
  "payType": "2",
  "payChannel": "HFDG",
  "payStatus": 2,
  "feeAmount": 0.60,
  "remark": "订单备注",
  "payTime": "2023-11-28 12:34:56",
  "createTime": "2023-11-28 12:30:00",
  "timestamp": 1701148496000,
  "sign": "abc123def456..."
}
```

参数说明：


|             |            |     |                                                    |
| ----------- | ---------- | --- | -------------------------------------------------- |
| 字段名         | 类型         | 必填  | 说明                                                 |
| orderNo     | String     | 是   | 商户订单号                                              |
| merchantNo  | String     | 是   | 商户号                                                |
| orderAmount | BigDecimal | 是   | 订单金额（元），精确到小数点后2位                                  |
| payAmount   | BigDecimal | 否   | 实际支付金额（元），精确到小数点后2位                                |
| payType     | String     | 是   | 支付类型（如：0：ALIPAY、2：WECHAT_JSAPI）                    |
| payChannel  | String     | 是   | 支付渠道（如：HFDG）                                       |
| payStatus   | Integer    | 是   | 支付状态：1-待支付 2-支付成功 3-支付失败 4-已退款 5-部分退款 6-已取消 7-重复支付 |
| feeAmount   | BigDecimal | 否   | 手续费（元），包含支付手续费和平台手续费                               |
| remark      | String     | 否   | 备注信息                                               |
| payTime     | String     | 否   | 支付完成时间，格式：yyyy-MM-dd HH:mm:ss                      |
| createTime  | String     | 否   | 创建时间，格式：yyyy-MM-dd HH:mm:ss                        |
| timestamp   | Long       | 是   | 当前时间戳（毫秒）                                          |
| sign        | String     | 是   | 签名，用于验证通知真实性                                       |


### 2.3 响应要求

商户系统处理成功后，必须返回以下响应：

- HTTP 状态码: 200
- 响应内容: success（字符串，不区分大小写）



## 三、退款回调通知

### 3.1 接口要求

- 请求方式: POST
- Content-Type: application/json
- 通知地址: 商户在发起退款时提供的 notifyUrl

### 3.2 请求参数

请求体（JSON格式）：

```JSON
{
  "merchantNo": "M123456",
  "orderNo": "20231128123456789",
  "reqSeqId": "R20231128123456",
  "transStat": "S",
  "ordAmt": 100.00,
  "transDate": "20231128",
  "transTime": "123456",
  "transFinishTime": "2023-11-28 12:35:00",
  "remark": "退款备注",
  "timestamp": 1701148500000,
  "sign": "xyz789abc123..."
}
```

参数说明：


|                 |            |     |                               |
| --------------- | ---------- | --- | ----------------------------- |
| 字段名             | 类型         | 必填  | 说明                            |
| merchantNo      | String     | 是   | 商户号                           |
| orderNo         | String     | 是   | 商户订单号                         |
| reqSeqId        | String     | 是   | 退款请求流水号                       |
| transStat       | String     | 是   | 退款交易状态：S-成功 F-失败 P-处理中        |
| ordAmt          | BigDecimal | 是   | 退款金额（元）                       |
| transDate       | String     | 是   | 退款交易发生日期，格式：yyyyMMdd          |
| transTime       | String     | 是   | 退款交易发生时间，格式：HHmmss            |
| transFinishTime | String     | 否   | 退款完成时间，格式：yyyy-MM-dd HH:mm:ss |
| remark          | String     | 否   | 备注信息                          |
| timestamp       | Long       | 是   | 当前时间戳（毫秒）                     |
| sign            | String     | 是   | 签名，用于验证通知真实性                  |


### 3.3 响应要求

商户系统处理成功后，必须返回以下响应：

- HTTP 状态码: 200
- 响应内容: success（字符串，不区分大小写）

## 四、签名验证

### 4.1 签名算法

系统使用 RSA 算法对通知内容进行签名，商户需要使用平台公钥验证签名的真实性。

### 4.2 验证步骤

1. 接收通知参数：获取所有参数（除 sign 字段外）
2. 参数排序：将参数按字段名ASCII码排序
3. 构建签名串：按 key=value&key=value 格式拼接
4. 验证签名：使用平台公钥验证 sign 字段

### 4.3 签名验证伪代码

```Java
// 1. 移除 sign 字段
Map<String, Object> params = removeSignField(notifyParams);

// 2. 按 key 排序并拼接
String signContent = buildSignContent(params);

// 3. 使用平台公钥验证签名
boolean valid = RSAUtils.verify(signContent, sign, platformPublicKey);
```

## 五、注意事项

### 5.1 幂等性处理

- 商户系统可能收到重复通知，请做好幂等性处理
- 建议使用 orderNo + reqSeqId（如有）作为唯一标识

### 5.2 安全性

- 必须验证签名：确保通知来自皓臻支付系统
- 必须验证商户号：确保通知是发给自己的
- 必须验证金额：确保金额与订单一致

### 5.3 响应时效

- 建议在 5秒内 完成处理并返回响应
- 超时将触发重试机制

### 5.4 异常处理

- 如果商户系统暂时无法处理，建议返回非 200 状态码或非 "success" 内容
- 系统会自动进行重试
- 不要在处理失败时返回 "success"，否则将不会重试
